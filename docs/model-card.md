# Model / System Card: Claims Fraud-Investigation Copilot

| Field | Value |
|---|---|
| System | LangGraph multi-agent SIU copilot (`src/graph.py`), version 1.0, BC-AAIE-HACK-09 |
| Model | **Google Gemini** (only provider). Default model **`gemini-3.5-flash-lite`** for the agents and the DeepEval judge (`evals/judge.py`), configurable via `GEMINI_MODEL` / `GEMINI_JUDGE_MODEL`; agents run at `thinking_level=low`. **The committed evidence (traces, eval, reports) was generated with `gemini-3.5-flash`** before the default was changed to reduce cost. |
| Local models | `sentence-transformers/all-MiniLM-L6-v2` (playbook + memory embeddings); spaCy `en_core_web_sm` inside Microsoft Presidio (PII detection) |
| Retrieval | FAISS `IndexFlatIP` over 11 synthetic playbooks, one chunk per section (`src/tools/rag_tool.py`) |
| Data | **100 % synthetic**: 12 flagged claims, 43 historical claims, a cross-carrier index and case assignments generated by `scripts/generate_synthetic_data.py` (seed 42); playbooks in `data/policy_corpus/`. No real people, policies or insurers. |
| Owner | SIU Product Owner (accountable); ML Engineer (model and evaluation); Security Engineer (guardrails); see `docs/risk-register.md` |

## Intended use
- **Users:** Special Investigation Unit (SIU) investigators and SIU lead reviewers.
- **Tasks:**
  - for a flagged claim, assemble the claim history;
  - correlate red-flag indicators;
  - retrieve and cite the matching fraud-scheme playbook;
  - draft an investigation case file recommending **close / monitor / refer_to_siu**;
  - answer follow-ups within the same session or a later one.
- **Role:** decision *support*. The copilot drafts; a human SIU reviewer signs off every refer / deny / escalate
  decision (`src/agents/finalize.py::make_human_gate`).

## Out of scope
- **Adverse decisions:** it never denies, pays, settles or closes a claim, and never contacts claimants.
- **Protected attributes:** it doesn't score or profile claimants on them (none exist in the data model,
  `mcp_server/claims_data.py`).
- **Non-SIU questions:** they're declined (`src/agents/writers.py::make_out_of_scope`).
- **Fraud enablement:** requests to commit or conceal fraud are refused
  (`src/guardrails/input_guard.py::check_input`, validator `FraudEnablement`).
- **Real data:** production claims or personal data need a new privacy review and re-evaluation first.
- **Deployment:** containerised or cloud deployment is out of scope for this cut.

## How it works (summary)
1. The input guardrails and access control check the request.
2. Memory is recalled and the conversation summarised.
3. Gemini classifies the intent.
4. A deterministic supervisor routes the claim through three workers:
   - **history** (MCP `get_claim_history` and `find_linked_claims`, with claimant text quarantined);
   - **indicators** (MCP `score_red_flags` plus the indicator catalog resource; score and tier come from the tool);
   - **playbook** (agentic RAG with citation validation).
5. The case writer drafts the file.
6. The output guardrails and risk classification check it.
7. Memory is written, and the human gate pauses for sign-off where required.

## Performance: evidence from the final run

**Evaluation** (`reports/eval_report.json`; 22 golden cases, DeepEval judge = Gemini):

| Metric | Result |
|---|---|
| Task accuracy (intent, tier, action, scheme + citation, sign-off gate, injection quarantine, safety behaviour, no PII, no auto-action) | **22 / 22 = 100 %** |
| Investigation action accuracy / scheme-match accuracy / safety pass rate | 100 % / 100 % / 100 % |
| Hallucination rate (DeepEval `HallucinationMetric`, case hallucinated if > 20 % of evidence contradicted) | **0 %** (grounding score mean 1.0 over 16 judged cases) |
| Faithfulness (mean) / answer relevancy (mean) / GEval case correctness (mean) | 0.994 / 1.00 / 1.00 (2 correctness judgements lost to API credit exhaustion, F-7) |

**Red team** (`reports/redteam_results.json`): 12/12 attacks defended offline in the final run. Run 1 defended 12/12
live on Gemini (`evidence_archive/run-1/reports/redteam_results.json`). The attacks cover direct and indirect
injection, prompt extraction, PII exfiltration, cross-queue and claimant-portal access, auto-adverse action,
role-play jailbreak, fraud enablement, encoded instructions and context stuffing.

**Golden signals** (`reports/golden_signals.json`, derived from Phoenix):

| Signal | Value |
|---|---|
| End-to-end turn latency | p50 2.5 s / p95 29.9 s (58 runs) |
| LLM spans | p50 2.4 s / p95 6.5 s |
| Tool spans | p50 10 ms / p95 101 ms |
| Tokens | 142.8k in / 53.9k out (19.9k reasoning) |
| Error-span rate | 2.4 %, all from the 402 credit event (F-7) |

Cost figures there use *placeholder* prices, not verified `gemini-3.5-flash` rates (see Limitations).

**Memory:** verified across two separate processes (`logs/memory_test.log`, 6/6 checks).

## Limitations
- **Synthetic and small.** 12 flagged claims and a 22-case golden set. The results show the system behaves as
  designed; they are not a statistical estimate of accuracy on real claims.
- **Hand-set rules.** The fraud score comes from 18 hand-weighted rules (`mcp_server/claims_data.py::INDICATORS`),
  not a learned model. It is transparent, but real use would need calibration against labelled outcomes.
- **Self-judging.** The LLM judge is the same model family as the agents, so self-preference bias is possible. The
  deterministic checks, which don't depend on the judge, are the primary accuracy measure.
- **Scope of the red team.** The final run's red team ran offline. The defences are deterministic guardrails, and
  run 1 verified them live.
- **Cost estimates.** They use configurable placeholder prices; actual Gemini billing for this project was higher.
  Verify current pricing and count judge calls before paid runs.
- **Coverage.** English only. Presidio uses the small spaCy model, which trades recall for speed.
- **Phoenix start-up patch.** The in-process launch relies on a documented patch to its 5 s start-up timeout
  (`src/observability/tracing.py::init_tracing`).

## Known failure modes (from our own runs; details, evidence, root cause and fix in `docs/failure-analysis.md`)

| ID | Failure mode | Mitigation now in place |
|---|---|---|
| F-1 | Cold start of the local NLP / embedding models inside the first request (45 s) | warm-up at start-up (`src/runner.py::Copilot.warm_up`) |
| F-2 | Side-effects before `interrupt()` repeat on resume (duplicate audit) | separate `request_signoff` node |
| F-3 | Evaluation-metric polarity change (DeepEval 4.x) misreported hallucination | explicit grounding definition in `evals/run_eval.py` |
| F-4 | Judge false negatives from mismatched criteria and truncated evidence | generic criteria + per-facet evidence |
| F-5 | Model paraphrased an indicator code wrongly without the catalog | catalog injected into answer context |
| F-6 | Token and cost not attributable to agents | span-tree attribution in `scripts/span_analytics.py` |
| F-7 | Provider credit exhaustion (HTTP 402) mid-run | non-retryable → deterministic fallback; `COPILOT_FORCE_OFFLINE`; `scripts/finalize_offline.py` |

Residual model-level risks: an LLM narrative may still overstate or mis-phrase evidence. That's why scores and actions
are tool-anchored and policy-enforced, citations are validated, and adverse outcomes need a human.
